# 张量运算的布局约定

## 从一次真实的广播错位说起

RoPE 里，x 是 (N, L, H, D)，cos 表取行后是 (L, M)（M = D/2）。想把每个位置的 cos 乘到对应 token 上，直接乘：

```python
x_a * cos    # x_a: (N, L, H, M), cos: (L, M)
```

报错或数值错位。原因在广播有一条硬性规则：**从右往左逐轴对齐**。

## 广播：从右往左逐轴对齐

两个数组相乘时，维度从最后一位开始逐对比较：

| 情况 | 结果 |
|------|------|
| 两轴相等 | 直接通过 |
| 一方是 1 | 复制扩展（1 变成对方的长度） |
| 其他 | 报错 |

不 reshape 直接乘：

```
(2, 5, 3, 2)     # x_a: N=2, L=5, H=3, M=2
      (5, 2)     # cos: L=5, M=2
```

从右往左：2 对 2 ✓，接着 5 对 3 ✗——cos 的 L（5）停在了 x 的 H（3）的槽位。H 碰巧等于 L 时数值错位，不等时直接报错。

reshape 成 (1, 5, 1, 2)：

```
(2, 5, 3, 2)
(1, 5, 1, 2)
```

1 对 2（复制到 2），5 对 5，1 对 3（复制到 3），2 对 2。四个槽位全对上。

## 1 是占位符：值无意义，位置有意义

广播比较时，1 永远是"复制"那一边，它的值不参与实质比较。但它的位置决定一切——它把 L 推到和 x 的 L 同一个槽位。删掉任何一个 1，后面的维度整体左移，L 就滑到 H 或 N 的槽位。

> reshape 加 1 不是在给表加内容，是在给维度**定位**。

## 布局操作族：reshape / swapaxes / stack

这几个操作不改变数据的数值（不增删、不重排），只改变"怎么解释"：

- `reshape`：按行优先顺序把元素重新切成别的形状。返回新数组，不改原数组——必须重新赋值
- `swapaxes`：交换两个轴，布局转换器
- `stack`：沿新轴把多个数组并排（`mx.stack([a, b], axis=-1)` 把 (…, M) 的两份变成 (…, M, 2)）

它们的存在是因为每个算子对布局有硬性假设：matmul 要求最后两维是矩阵、softmax 要指定 axis、attention 约定最后两维是 (L, D)。

**省略号：切片里"前面所有维度"的缩写。** `x[..., :M]` 里的 `...` 展开成和数组维度数匹配的冒号序列：4 维数组就是 `x[:, :, :, :M]`，5 维就是 4 个冒号。它存在是因为维度多时手写冒号容易数错。`:M` 取前 M 个元素，`M:` 取 M 到末尾。切片只做"按位置取子集"，不搬数据、不算数学——数组的一部分被拿出来，剩下的索引原样保留。

## 标签对齐 vs 位置对齐

二维表格（pandas）里，"对齐"按列名/索引值匹配——标签相同才对上，标签不同补 NaN。这是**标签对齐**。

张量广播是**位置对齐**——按轴序号匹配，靠维度相等或 1 扩展，没有"名字"这个概念。

两者不是包含关系：

- 维度表达能力上，张量更广（任意维，pandas 固定二维）
- 但 pandas 底层就是 ndarray（张量），pandas = 张量 + 标签层，标签对齐是额外加的规则，不是张量规则的延伸

一句话：张量是位置对齐的世界，pandas 是标签对齐的世界。pandas 用张量当存储，对齐规则另算。

## 对齐的直觉：两个表并排

把广播想成把两个表并排放：行要一行对一行（L 对 L），列要对齐（M 对 M）。x 有 4 个维度，cos 只有 2 个，就把它当成"只有列、没有前面维度"的表——但张量没有"自动居中"这回事，它从右往左贴齐，所以 L 贴到了 H 的位置。补 1 就是明确告诉它"L 在第 1 个槽位"。
